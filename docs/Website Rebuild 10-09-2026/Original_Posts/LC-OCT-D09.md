# LC-OCT-D09 A useful evaluation changes a decision

I want an evaluation to change something the team can name.

Consider an illustrative assistant that handles returns. A polite final answer is not enough if it used the wrong policy or repeated a refund action. Review the task, the evidence, the tool behaviour and the outcome separately.

Then decide what to change: a permission, a workflow, an evaluator or a human review point. The value is in that connection between evidence and architecture.
