# LC-OCT-D11 What evidence would you ask for?

A demo is usually a short visit. Your system has to live there.

Imagine the useful next question being: what happened on the requests we did not choose for the presentation?

I want to see failures, uncertain evidence and awkward tool results, as well as the examples that worked. Then we can discuss which finding would change the design.

## Spoken script

Imagine a team showing an agent that handles a returns request beautifully. The answer is clear. The tool works. Everyone can see the idea.

Now I would ask to see the requests we did not put in the demo.

What happened when the policy was unclear? What happened when the tool failed? Did the assistant recognise a repeated request, or was it about to repeat the action?

Those questions are not there to spoil a good demonstration. They help us understand what we have actually learned from it.

I would want the team to connect each finding to a decision. If this class of requests keeps failing, what do we change? The workflow? A permission? The evidence we retrieve? Or the evaluation itself?

Sometimes the next step is a small test, not a bigger design. But we should be able to explain why that test matters.
