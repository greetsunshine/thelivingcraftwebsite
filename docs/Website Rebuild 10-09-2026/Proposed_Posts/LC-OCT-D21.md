# LC-OCT-D21 Before the agent changes something

The tool timed out. Did the refund fail, or did only the reply fail?

In this illustrative situation, pressing retry is suddenly an architecture decision.

Once an agent can change something outside the model, we need to know who permits the action, how duplicates are recognised and what happens when the outcome is uncertain.

## Spoken script

Imagine asking a tool to issue a refund. You wait. Then you get a timeout.

Did the refund fail? Or did the refund happen and the response disappear?

If we cannot tell, “try again” is not much of a plan. We might be asking the system to pay twice.

This is an illustrative example, but the same question appears whenever an agent changes something outside the model: sending a message, granting access, moving money.

I would start with the authority to act, the evidence required and a way to recognise the same request. Then I would make the uncertain outcome an explicit state, with a defined way to check or escalate it.

The control has to exist in the tool and workflow. We should be able to inspect what happened, not just hope the prompt covered it.
