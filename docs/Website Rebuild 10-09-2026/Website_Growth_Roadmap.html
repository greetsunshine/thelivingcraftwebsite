Agent Design Check functional scope

Offer an ungated browser checklist. Use structured yes/no/not-yet-defined answers about purpose, evidence, tool permissions, external actions, evaluation, uncertainty/recovery and ownership. Include a built-in illustrative example so visitors can understand each question without uploading company materials.

The result shows which questions remain unanswered, why they matter and a prioritised set of next steps with guide links. Distinguish a reported gap from a missing answer. Use transparent rules reviewed by Sunil, not a model-generated readiness score. All-unknown input returns a starting checklist, not a failure grade. A claim that every box is addressed still requests evidence rather than certifying production readiness.

Process answers in the browser. Offer a downloadable text/print summary without login; retain no architecture answers on the server by default. Optional email signup follows the result and is separate from using the tool. Track starts/completions only with appropriate analytics permission. No lead record is created from anonymous use.

After rubric approval, package the same method as Claude and Codex architecture-review skills. Review only user-selected material; return referenced observations, questions, limitations and next actions. Include a sample input/report, usage guidance and versioned rubric. Verify each host independently; no cross-host compatibility claim before tests. Do not execute or modify the user’s code as part of the review by default.

Search and answer quality requirements

For each page, author the direct answer first, then who/when it applies, a concrete explanation or worked example, supporting evidence, limitations and the appropriate next step. Put important text in accessible HTML. Video transcripts, tables and diagrams support the explanation rather than replacing it. Publish author/reviewer identity and meaningful revision dates; never refresh dates without content review.

Use descriptive page titles, one clear primary heading, semantic sections, descriptive links, canonical URLs, a current XML sitemap and crawlable internal links. Validate mobile readability and content parity between rendered HTML and source. Structured data may describe the organisation, person, article, breadcrumbs, course or video only when the visible content supports it. Do not manufacture reviews or expect FAQ markup to secure rich results.

Google states that its AI features use the same SEO foundations and require no special AI files or markup. Search snippets must remain eligible; robots, CDN rules and rendering can block access. OAI-SearchBot and GPTBot serve separate search/training purposes; Perplexity also documents its search crawler. Verify search access using the current official guidance without changing training preferences by implication. These measures support discoverability, not a guarantee of rankings or citations.

Twelve question visibility sample

Use the same wording at baseline and monthly review. These are selected research questions, not validated search-volume targets. Keep organic referrals, AI referrals and manual citation observations separate.
